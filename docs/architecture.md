# Runtime ownership

## Providers

Usage observations remain owned by the selected native adapter. Concurrent reads share its pending refresh; failed refreshes retain explicitly stale observations, and account changes discard all quota, credit and reset metadata. HQ stores no derived quota history or second usage cache. Credit balances remain opaque exact strings, and independent account/model meters are never aggregated.

The runtime registers built-in and trusted Node-supplied provider factories at construction. It creates each adapter only when that provider is selected. Status and database-backed reads do not require a native CLI. Provider IDs flow through contracts, cursors and persistence; core actions, sessions and skills route through the registry. Native protocol parsing and invocation spelling stay with each adapter.

The registry binds callback identity, bounds operations, and validates consumed evidence. Optional capability failures remain separate from session control. Invalid control state or identity quarantines its source, and bounded per-provider lifecycle queues contain overload. A store failure affects shared persistence. Adapters own partial-startup cleanup and native process lifetime; runtime shutdown confirms cleanup before releasing ownership. Version labels are diagnostic metadata, never admission gates. Native input, settings, permissions and authentication remain with the installed harness.

Codex sessions run on Codex's shared app-server daemon, which also hosts terminal sessions. The adapter runs `codex app-server daemon start`, which returns at once when the daemon is running, then connects through `codex app-server proxy`. The daemon's control socket speaks WebSocket and the proxy forwards raw bytes, so the adapter performs the upgrade, masks its frames and bounds each message to the IPC frame limit. The proxy notices a stopped daemon only when it next writes, so the adapter pings every 10 seconds and fails the transport when a ping goes unanswered; the Codex cohort then becomes uncertain and nothing is resent. The next Codex request opens a new connection, so a daemon restart needs no HQ restart. Closing HQ's connection leaves the daemon and terminal sessions running. Extra skill roots travel as capability roots of the threads HQ starts, because the daemon applies `skills/extraRoots/set` to every session.

Sessions another client drives are observed rather than controlled. Codex reports them through the daemon's status broadcasts, filtered to the allowed workspaces; Claude reports them through a runtime-owned poll of `claude agents --json`, whose complete list closes every session missing from it. Observed states live in their own table. Triggers on that table and on managed thread states append every change to one transition log with a monotonic sequence, so no write path can skip a transition, and each insert prunes a bounded batch of entries older than seven days.

Account and MCP observations use the provider boundary and bounded native catalogs, without exposing configuration credentials. Catalog joins last only for an in-flight read and are invalidated by native reload/auth changes. Native extension controls and global account changes use the existing action ledger. Global receipts retain provider identity and control outcome; URLs, native login IDs and tokens stay in bounded runtime memory. Exact authentication completion does not start a model turn or advance queued work.

Account changes require the provider's managed sessions to be closed. Pending provider-wide changes fence new execution through the same atomic admission transaction; the other provider stays available. Restart retains outcome uncertainty without replaying authentication. Native process ownership is shared by structured transports and the noninteractive Claude logout command, with verified POSIX group shutdown. Idle Claude processes close: the session-less read process after 5 minutes unused, and a controlled session's process 60 minutes after its last turn, its settings, agent list and skills catalog kept in memory until input reopens it with `--resume`. That parked state is not persisted.

HQ preserves native session, parent and fork identities separately from its own managed thread UUID. Confirmed immutable lineage survives restart and enriches native reads that omit those fields; contradictions fail instead of replacing recorded relationships. A fork has a new managed identity and no inherited plan binding. Lifecycle changes use the same action ledger and uncertainty rules as input. Compaction admission and native completion remain separate. Archive releases control after confirmed background cleanup, while unarchive never resumes execution.

Native model catalogs and effective settings remain authoritative in each provider. Configuration reads project known fields and bounded native agent/profile metadata, without exposing whole settings documents. Model and effort changes accompany the next explicit input; startup settings accompany create or idle resume. No global configuration files are rewritten. Temporary Claude workspace reads are bounded to four owned native processes. Their cancellation signal closes the transport, and shutdown waits for every starting or ready lane; unconfirmed cleanup cannot release ownership. Native observations are refreshed rather than kept in a parallel configuration cache; the bounded in-memory session metadata retains only startup acknowledgement fields that a later native read cannot return.

File input admission records canonical references and hashes rather than embedding bytes in commands. Dispatch rereads checked descriptors and rejects a changed queue binding before sending native input. Native adapters encode those verified bytes into supported image/document/text inputs. Fixed count and byte limits bound both reads and worst-case native JSON transport. No remote fetching or file-content cache is involved.

Complete final results are separate from the bounded live/history presentation. The adapter validates requested structured output and records exact bounded values with native completion in the action ledger. Selected receipts retrieve them after restart; paged action reads select metadata only. Tool output remains in native history. Output buffers are limited to the current controlled turn, and completion or confirmed control release discards them. Claude output schemas require an idle process restart; Codex applies them per turn. Directed dispatch installs the shared HQ envelope through an idle Claude restart using the same native identity and retained settings. Later ordinary turns unwrap null-request envelopes into normal Markdown results.

Native request bodies stay in the controller’s bounded live prompt map. SQLite keeps approval identity, exact turn/runtime correlation, state and reply-action identity; indexed seek queries return durable metadata with optional live presentation. Restart or loss of the native connection expires pending requests. Pipe writes do not establish response consumption, and unanswered delivery uncertainty never triggers a resend. Plan authority and native permission responses remain independent.

Bounded session evidence uses the native history boundary and rechecks workspace authorization per read. Exact references bind normalized UTF-8 text to provider, session, turn, item and hash. A partial-page continuation validates its content digest before returning another body fragment. Source pages stay bounded; no transcript body cache is kept. Claude's worker seeks current-chain UUID/kind/offset indexes and rereads only selected records after incremental indexing. Indexing scans each transcript in one reused 64 KiB chunk and decodes each record once; a record that spans chunks is read again whole into one reused buffer, instead of being copied again for every chunk.

Input provenance joins exact acknowledged native input identities and text fingerprints with action records. Authenticated host text additionally matches its browser admission's selected thread and fingerprint. HQ saves hashes rather than another copy of ordinary input. Native user roles and quoted feedback remain unknown unless that correlation succeeds. Dispatched coordination inputs correlate to an agent-input origin rather than operator approval. Every historical item has an untrusted content boundary and grants no authority.

## Storage

Agent tools derive identity from provider-bound native callbacks or private, revocable stdio credentials. Each call waits for already received native lifecycle evidence, then validates the exact runtime/session binding and current task membership. Credentials are random opaque values stored only in 0600 files under an owned 0700 system temporary directory and hashed lookup keys in runtime memory. Session close revokes and removes the file; reconnect creates a fresh lease, and runtime shutdown removes its directory. Ordinary native metadata readers receive no bridge configuration. The installed MCP SDK owns framing and protocol negotiation; stdout contains protocol traffic only.

Both direct native callbacks and IPC bridge calls participate in storage admission, so host maintenance drains admitted tools and rejects new ones. Tool descriptors are built lazily once per runtime and copied to native registrations. Mutable membership, permission and inbox reads remain uncached; their indexed queries select bounded metadata. Non-identity operations retrieve only the selected authorization context rather than a discovery page.

Native children with verifiable same-workspace parent lineage resolve to their owning managed session. Claude's shared native MCP credential also represents its owner. Neither native session-tree IDs nor names become new agent IDs. Independently addressable participants use managed spawning through the native action ledger. Its transaction records the exact parent/request digest, reserves cumulative task capacity, creates the managed thread and copies effective task permissions, narrowed to the active invocation when spawning from delegated work. Failed admission rolls those reservations back; native creation uncertainty retains them and reuses the original receipt without a resend. No agent tool issues grants or changes native permission policy.

Collaboration task ownership and membership use immutable managed-thread UUIDs, independent of provider and native session identity. Host-issued grants select exact skills, modes, effects and workspace/path scopes. Admission rechecks task policy, membership and the selected grant revision. Role labels, publications and evidence references carry no operator or plan authority. Paused members retain history access; claiming work requires current active membership.

The SQLite worker commits each metadata mutation, its digest/result receipt and delivery intent together. Publications are immutable. Root requests retain assignment and resolution independently of subscriptions, read positions, acknowledgements and native delivery. Subscriber fan-out advances in transactions of at most 32 subscriptions, with a durable high-water boundary and progress position. Restart resumes pending batches; a failed transaction remains pending and exposes a recovery failure through status. Each background batch participates separately in maintenance admission, and shutdown drains its current batch before closing SQLite. Information, read and acknowledgement traffic never starts inference. Authorized request intent is dispatched separately through the native action ledger.

Directed dispatch stores its pending action identity on the request and its immutable invocation binding on the existing native action. One partial unique index holds an agent's active dispatch through terminal outcome collection, across tasks. A task's active capacity and cumulative automatic-turn count are reserved in that same worker transaction. Busy requests retain intent without a model polling turn or a second execution ledger. Startup, metadata authority changes and persisted native lifecycle events wake one bounded recovery loop. Every admitted request rechecks current grants, lifecycle, native ownership and exact plan authority before native submission. Uncertain input retains its original binding and never resends automatically.

Optional skills use the recipient’s native catalog and presentation, with exact arguments/mode read from the verified invocation. The action binds the immutable coordination packet independently of native formatting. A skill grant permits entry within its scope and never replaces later approvals. Missing skills retain blocked intent without substitute prompts.

Native structured envelopes carry completed, waiting-children, needs-input, paused or failed outcomes. The worker atomically saves an exact report, immutable reply, request transition, return delivery intent and collection receipt. A read-only assessment needs no publishing permission or additional model turn. Native acknowledgements mark delivery separately from acknowledgement and outcome. Checkpoint input selects the exact prior action; pause resumption also selects current lifecycle revisions. Runtime diagnostics identify their source. A canceled uncertain request releases its binding only after explicit ownership recovery confirms native idle state; its native receipt stays uncertain and the collection records the recovery action.

Message summary/body and operator-identity reads select bytes explicitly so embedded NULs survive the Node SQLite boundary. Reports are authoritative SQLite BLOBs capped at 1 MiB, with incremental UTF-8 capture and SHA-256. Report reads select bounded substrings and bind continuation to visibility, identity and content hash. FTS5 supplies ordered message/report hits through two bounded index seeks; selected report excerpts may read their fixed-capacity bodies inside SQLite, while Node receives only bounded excerpts. No transcript mirror, report cache or general artifact storage is introduced. Snapshots include the exact payloads as part of the database.

Parent links bind child publication to the exact active native action. Each request holds at most 32 named direct children, a wait generation and one continuation reservation. Wait registration and child collection inspect the same bounded primary-key set transactionally, including early results and unconsumed requester clarifications. Native acceptance consumes only included clarification action identities and marks included report deliveries. Parent waiting releases native capacity while retaining plan authority; every continuation reuses the normal admission and uncertainty path. Startup reevaluates saved waits without polling models or creating a dependency table or second queue. Operator questions, interruptions and paused/revoked parents remain blocked. Late child outcomes cannot restart ended parents.

Collection reads seek indexed sequences within a fixed high-water boundary, select summaries and fit serialized byte budgets. Subscribed streams follow subscription sequence; other lists use their record sequence. Request lists for an agent merge two bounded indexed seeks for target and assignee. FTS5 indexes task and stream tokens together with summary/body content, so search narrows authorization scope before retrieving records. No message or history body cache is kept; these records and notification positions are authoritative state. Content has fixed publication limits and remains durable without automatic deletion or semantic summarization.

One SQLite worker owns HQ persistence, with its young generation capped at 16 MiB. The complete definition, including provider history indexes, is src/store/schema.sql. Fresh initialization creates the schema and its singleton hq_schema stamp, containing the HQ schema hash, the action-key fingerprint and the package version that wrote it, in one transaction. Reopening validates that stamp through a read-only connection before opening a writer and rejects a mismatched private key. This preserves rejected database bytes and their WAL instead of triggering SQLite's close-time checkpoint. Application-owned objects are outside this stamp. HQ leaves user_version with the host. The package reads only its current schema: any other stamp is refused with an error naming the package version that wrote it, and storage is never migrated.

All HQ tables, indexes and named constraints use the hq\_ prefix. Hosts own their application prefixes and definitions. They may open a separate connection using the canonical path and connection settings supplied by the Node runtime. Prefixes express ownership within a trusted process; they do not protect against another process with access to the file. Direct application writes to HQ-owned tables are unsupported.

Maintenance closes new HQ admission, drains admitted operations and their nested calls, and waits for earlier worker commands. Native evidence needed to finish admitted work continues during the drain. It refuses active native execution and unresolved plan writes. During the host callback, new native event persistence waits for release through the existing bounded event lane; an already accepted scheduled stop also waits. The host callback owns its connection and must not call HQ, start native work or leave its transaction open. Callback failure releases admission without classifying the host's SQL effect as rolled back.

A host connection and an HQ API call cannot share one SQLite transaction. Cross-boundary work needs idempotency and reconciliation owned by the application. SQLite permits one writer at a time; unrelated host connections must cooperate with maintenance. The API reference owns connection settings, signatures and error contracts.

Snapshot capture is ordinary admitted work, so maintenance excludes it while native work continues. It holds the coordination metadata lock, retaining prepared plan writes as recovery evidence. The SQLite worker performs a WAL-aware backup through its own connection in bounded steps, interleaved with native evidence; writes from another connection would restart or split it, so hosts keep their own tables quiet. Plans registered in the captured database are then copied one at a time under shared document locks. Each record keeps the revision computed from its copied files next to the revisions the captured database's thread bindings record, and a mismatch marks the plan changed. An indexed registration table records durable plan references without repeated JSON scans. files and the JSONL inventory are streamed, with an exact final completion marker. No artifact cache is used because each capture/inspection must establish current exact bytes.

Offline verification and restore run in a separate worker. Restore refuses a snapshot from another schema, validates a staged copy before exposing new private state, preserves reports and pending intents, and invalidates current automation, grants, native ownership, live approvals and the execution scope of plans that changed during capture. Source roots and paths remain evidence; the host must select allowed roots anew. Repository files, native histories/authentication and remote durability remain outside the snapshot. See [recovery](recovery.md).
