# Runtime ownership

## Providers

The runtime registers built-in and trusted Node-supplied provider factories at construction. It creates each adapter only when that provider is selected. Status and database-backed reads do not require a native CLI. Provider IDs flow through contracts, cursors and persistence; core actions, sessions and skills route through the registry. Native protocol parsing and invocation spelling stay with each adapter.

The registry binds callback identity, bounds operations, and validates consumed evidence. Optional capability failures remain separate from session control. Invalid control state or identity quarantines its source, and bounded per-provider lifecycle queues contain overload. A store failure affects shared persistence. Adapters own partial-startup cleanup and native process lifetime; runtime shutdown confirms cleanup before releasing ownership. Version labels are diagnostic metadata, never admission gates. Native input, settings, permissions and authentication remain with the installed harness.

Account and MCP observations use the provider boundary and bounded native catalogs, without exposing configuration credentials. Catalog joins last only for an in-flight read and are invalidated by native reload/auth changes. Native extension controls and global account changes use the existing action ledger. Global receipts retain provider identity and control outcome; URLs, native login IDs and tokens stay in bounded runtime memory. Exact authentication completion does not start a model turn or advance queued work.

Account changes require the provider's managed sessions to be closed. Pending provider-wide changes fence new execution through the same atomic admission transaction; the other provider stays available. Restart retains outcome uncertainty without replaying authentication. Native process ownership is shared by structured transports and the noninteractive Claude logout command, with verified POSIX group shutdown.

HQ preserves native session, parent and fork identities separately from its own managed thread UUID. Confirmed immutable lineage survives restart and enriches native reads that omit those fields; contradictions fail instead of replacing recorded relationships. A fork has a new managed identity and no inherited plan binding. Lifecycle changes use the same action ledger and uncertainty rules as input. Compaction admission and native completion remain separate. Archive releases control after confirmed background cleanup, while unarchive never resumes execution.

Native model catalogs and effective settings remain authoritative in each provider. Configuration reads project known fields and bounded native agent/profile metadata, without exposing whole settings documents. Model and effort changes accompany the next explicit input; startup settings accompany create or idle resume. No global configuration files are rewritten. Temporary Claude workspace reads are bounded to four owned native processes. Their cancellation signal closes the transport, and shutdown waits for every starting or ready lane; unconfirmed cleanup cannot release ownership. Native observations are refreshed rather than kept in a parallel configuration cache; the bounded in-memory session metadata retains only startup acknowledgement fields that a later native read cannot return.

File input admission records canonical references and hashes rather than embedding bytes in commands. Dispatch rereads checked descriptors and rejects a changed queue binding before sending native input. Native adapters encode those verified bytes into supported image/document/text inputs. Fixed count and byte limits bound both reads and worst-case native JSON transport. No remote fetching or file-content cache is involved.

Complete final results are separate from the bounded live/history presentation. The adapter validates requested structured output and records exact bounded values with native completion in the action ledger. Selected receipts retrieve them after restart; paged action reads select metadata only. Tool output remains in native history. Output buffers are limited to the current controlled turn, and completion or confirmed control release discards them. Claude output schemas require an idle process restart; Codex applies them per turn.

Native request bodies stay in the controller’s bounded live prompt map. SQLite keeps approval identity, exact turn/runtime correlation, state and reply-action identity; indexed seek queries return durable metadata with optional live presentation. Restart or loss of the native connection expires pending requests. Pipe writes do not establish response consumption, and unanswered delivery uncertainty never triggers a resend. Plan authority and native permission responses remain independent.

Bounded session evidence uses the native history boundary and rechecks workspace authorization per read. Exact references bind normalized UTF-8 text to provider, session, turn, item and hash. A partial-page continuation validates its content digest before returning another body fragment. Source pages stay bounded; no transcript body cache is kept. Claude's worker seeks current-chain UUID/kind/offset indexes and rereads only selected records after incremental indexing.

Input provenance joins exact acknowledged native input identities and text fingerprints with action records. Authenticated host text additionally matches its browser admission's selected thread and fingerprint. HQ saves hashes rather than another copy of ordinary input. Native user roles and quoted feedback remain unknown unless that correlation succeeds. Every historical item has an untrusted content boundary and grants no authority.

## Storage

Collaboration task ownership and membership use immutable managed-thread UUIDs, independent of provider and native session identity. Host-issued grants select exact skills, modes, effects and workspace/path scopes. Admission rechecks task policy, membership and the selected grant revision. Role labels, publications and evidence references carry no operator or plan authority. Paused members retain history access; claiming work requires current active membership.

The SQLite worker commits each metadata mutation, its digest/result receipt and delivery intent together. Publications are immutable. Root requests retain assignment and resolution independently of subscriptions, read positions, acknowledgements and native delivery. Subscriber fan-out advances in transactions of at most 32 subscriptions, with a durable high-water boundary and progress position. Restart resumes pending batches; a failed transaction remains pending and exposes a recovery failure through status. Each background batch participates separately in maintenance admission, and shutdown drains its current batch before closing SQLite. Metadata operations never start inference.

Collection reads seek indexed sequences within a fixed high-water boundary, select summaries and fit serialized byte budgets. Subscribed streams follow subscription sequence; other lists use their record sequence. Request lists for an agent merge two bounded indexed seeks for target and assignee. FTS5 indexes task and stream tokens together with summary/body content, so search narrows authorization scope before retrieving records. No message or history body cache is kept; these records and notification positions are authoritative state. Content has fixed publication limits and remains durable without automatic deletion or semantic summarization.

One SQLite worker owns HQ persistence. The complete definition, including provider history indexes, is src/store/schema.sql. Fresh initialization creates the schema and its singleton hq_schema hash in one transaction. Reopening validates that stamp through a read-only connection before opening a writer. This preserves rejected database bytes and their WAL instead of triggering SQLite's close-time checkpoint. Application-owned objects are outside this stamp. HQ does not modify user_version or convert persisted state between schema definitions; use a fresh development state root after an HQ schema change.

All HQ tables, indexes and named constraints use the hq\_ prefix. Hosts own their application prefixes and definitions. They may open a separate connection using the canonical path and connection settings supplied by the Node runtime. Prefixes express ownership within a trusted process; they do not protect against another process with access to the file. Direct application writes to HQ-owned tables are unsupported.

Maintenance closes new HQ admission, drains admitted operations and their nested calls, and waits for earlier worker commands. Native evidence needed to finish admitted work continues during the drain. It refuses active native execution and unresolved plan writes. During the host callback, new native event persistence waits for release through the existing bounded event lane; an already accepted scheduled stop also waits. The host callback owns its connection and must not call HQ, start native work or leave its transaction open. Callback failure releases admission without classifying the host's SQL effect as rolled back.

A host connection and an HQ API call cannot share one SQLite transaction. Cross-boundary work needs idempotency and reconciliation owned by the application. SQLite permits one writer at a time; unrelated host connections must cooperate with maintenance. The API reference owns connection settings, signatures and error contracts.
